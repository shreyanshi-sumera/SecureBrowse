SecureBrowse Privacy Policy

Last Updated: October 2026

1. Overview

SecureBrowse is committed to securing your browsing experience without compromising your privacy. This policy outlines how we handle data and permissions within our browser extension.

2. What Data We Collect & Process

We believe in data minimization, and here is exactly what happens today:

  • Personal Information: The extension does not intentionally collect account credentials or profile information. However, a visible-text excerpt can include personal information displayed by a webpage, so consider this before enabling AI analysis.
  • URL Scanning: The extension sends the URL to the configured local threat-analysis backend. If it cannot connect, protection falls back to on-device heuristics; it does not send the scan to another backend.
  • AI Analysis: When the local Gemini backend is running, the current URL, up to 10 recent redirect URLs, page title, and up to 8,000 characters of visible page text are sent to Google Gemini for threat and betting-promotion analysis. Page text is not saved in local scan history. Form values, passwords, and other input values are not read or sent.
  • Scan History: The local Gemini backend stores scan results (URL, risk score, action, reasons, and timestamp) in a JSON file on your device. Page text and Gemini API keys are not saved in scan history. No SecureBrowse-operated server receives this data.
  • Local Storage: Your custom whitelists, blacklists, extension settings, blocked-domain records, and usage statistics are stored strictly on your local browser profile using Chrome's local/session storage APIs and are never uploaded or synced to any external server by the extension itself.

3. Why We Need Permissions

SecureBrowse requests permissions solely to execute core security features:

  • <all_urls> & Host Permissions: Required to run our dynamic DOM scanners that analyze loaded page content for malicious template structures (such as clone scams) and to process ad blocking.
  • declarativeNetRequest: Used to block dynamic trackers, advertising networks, and scripts directly at the network level before they load in your browser.
  • webNavigation: Required to monitor tab redirection timings and detect malicious redirection chains (redirect loops/hijacking).
  • storage: Used to store and maintain your custom rules, configurations, and protection levels locally.

4. Security Safeguards

By default, the extension communicates with a backend running on your own machine at http://127.0.0.1:8000 — this is plain HTTP, not encrypted, because the traffic never leaves your device. If you point this extension at a backend hosted anywhere other than your own machine, that connection should use HTTPS, and you are responsible for configuring that. An optional API key (sent as an X-API-Key header) can be configured in Settings to prevent other software on your device from calling your backend. No third-party analytics or tracker packages are integrated into the extension client code itself.
